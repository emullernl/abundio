# Terminal file links resolve through a watcher-aligned in-memory index

Path-ish substrings rendered inside a Pane's PTY — whether bare basenames in `ls` output, slashed paths in `git status` / `grep` / `tsc` / stack traces, or anything an Agent prints — become hover-underlined and plain-click-activatable when they resolve to a file inside the originating Workspace. Activation goes through `useExplorerStore.openFile(workspaceId, filePath)`, so the file lands in an existing file pane if one is already open in any Tab of that Workspace, or in a new Tab otherwise; trailing `:line[:col]` and `(line,col)` annotations populate `pendingGotoLine` so the editor jumps to the location. Detection runs through an xterm `Terminal.registerLinkProvider` registered alongside `WebLinksAddon` (`terminalManager.ts`), so hover is the only time the matcher runs and scrollback gets linked retroactively. The regex is intentionally permissive (it'll match arbitrary alphanumeric runs); precision comes from the index lookup downstream, which rejects anything that isn't an actual workspace file. The `WebLinksAddon` URL handler stays on plain-click activation as well: xterm's link layer intercepts clicks on a linked range before they reach the selection / focus / mouse-reporting paths, so there's no real collision — the cost is that text selections starting inside a linked path must begin outside the link's hot zone, which is the same trade-off every browser link has.

Hover must answer "does this path exist?" synchronously to return an `ILink`, which forces a choice between a maintained in-memory index and a stat-per-hover IPC call. We picked a per-Workspace in-memory file `Set<string>` built with the `ignore` crate (mirroring `search.rs`'s walk convention) on workspace activation, kept in sync via the existing `FsChange` events emitted by `file_watcher.rs`. Set membership is sync — no IPC, no flicker. The cost is a hard coupling: the index must align with the watcher's ignore set (`node_modules`, `target`, `.DS_Store`, `.git` internals), because an unfiltered index would silently drift on the first `npm install` — the watcher wouldn't forward those changes and the index would lie. Net consequence: paths under those directories don't underline in terminal output. Considered acceptable; clicking into `node_modules` is rare and the rest of the app (Explorer changes, full-text search) follows the same convention. The alternative — `fs_file_exists` IPC per hover candidate — was rejected because the ~ms-scale latency on hover would produce a perceptible flicker before the underline appears, and self-correcting drift isn't worth that UX regression for the dominant case.
