# Agent status hooks are provisioned into global agent config files

Abundio mirrors each Agent's lifecycle into its status indicator by registering hooks in that Agent's hook system. Hook payloads carry no Pane/PTY identity, so correlation rides on a per-PTY env var read by a small relay; and Agents load hooks only from global or per-project config. Redirecting each Agent's config home per-PTY would detach it from the user's auth and settings, so we instead merge Abundio's hook entries into the **global** agent config (`~/.claude/settings.json`, `~/.codex/hooks.json`, etc.).

Status hooks are **on by default**: the Settings toggle is opt-out, and a `persist` v2 migration also enables them for existing users who only ever saw the earlier off default. This means the relay is provisioned machine-wide on first launch without explicit user action, and the relay runs for every invocation of that Agent — not just inside Abundio. Accepted because the relay is a pure observer that exits immediately as a no-op when the Abundio PTY env var is absent and never alters the Agent's behaviour; Abundio removes only its own entries when the toggle is disabled; and the in-app toggle description discloses the global-config edit so it is not silent.
