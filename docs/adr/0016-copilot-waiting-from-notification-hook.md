# Drive Copilot's Waiting from the `notification` hook's `permission_prompt`, not `permissionRequest`

ADR-0015 absorbed Copilot's ambiguous `permissionRequest` (which fires for every permission-gated tool, even auto-approved, in the order `preToolUse → permissionRequest → postToolUse`) with a 1500ms output-quiet debounce. Copilot's `notification` hook now exposes a `notification_type`, and a genuine permission prompt arrives as `notification_type: "permission_prompt"` — observed to fire **only** on real prompts, not on auto-approved tools. We therefore replace the debounce wholesale: provision the `notification` hook with `matcher: "permission_prompt"` (Copilot filters at source — anchored `^(?:permission_prompt)$`) and map `notification → Waiting` directly. This removes the `permissionRequest`, `postToolUse`, and `postToolUseFailure` provisioning, the default `preToolUse → Working` mapping, and the entire `copilotWaitingDebounce` module — eliminating the per-tool loopback traffic and the sky-blue flicker that motivated ADR-0015 in the first place. **This ADR supersedes ADR-0015.**

The two prompt-tools that emit no `notification` — `exit_plan_mode` (plan review) and `ask_user` (multiple-choice) — keep their immediate-Waiting via a `preToolUse` hook whose `matcher` is scoped to just those tool names (`^(?:exit_plan_mode|ask_user)$`), so `preToolUse` no longer fires for every tool. A freshly-set Waiting dot is held against the permission prompt's *own render output* by a guard in `recordOutput` (agent-mode Waiting is overridden only by a keystroke or the next hook — the invariant `markIdle` already documents but `recordOutput` previously violated). It clears on the user's answer keystroke (digit/Enter → Working, ESC → Idle) or `agentStop → Ready`.

## Considered alternatives

- **Keep the debounce, just feed it from `notification` instead of `permissionRequest`.** Rejected: if `permission_prompt` is a clean genuine-prompt signal, the debounce is dead weight — deleting it is the entire point.
- **Filter `notification_type` in the frontend (no provisioning matcher).** Rejected: every notification would still POST to the loopback server and get logged per-tool — the transport-layer version of the overload this branch fights. The matcher filters at source and keeps `mapHookEvent` dumb (`notification` *is* Waiting, no payload parsing). Risk: a wrong matcher fires **never** (the codebase deliberately avoided a matcher for Gemini's undocumented permission token for exactly this reason) — mitigated by verifying the relay fires once with the matcher in place.
- **Drop `exit_plan_mode`/`ask_user` entirely.** Rejected: a silent regression to amber Working for plan/question prompts. A `toolName`-scoped `preToolUse` matcher preserves them at zero per-tool traffic.
- **Keep `postToolUse`/`postToolUseFailure → Working` as a clearing backstop.** Rejected: they fire for *every* tool (a per-tool POST + ~8 KiB log line each). The keystroke handler (Copilot prompts answer with digit/Enter), `agentStop`, and the `recordOutput` guard cover clearing without them.

## Known residuals

- **Load-bearing assumption: `permission_prompt` fires only on genuine prompts.** `github/copilot-cli#2586` (filed 2026-04-08, open) reports the `notification` hook firing with `notification_type: "permission_prompt"` for *every* tool execution in interactive mode, even already-approved ones. We rely on the observed clean behaviour for the current Copilot version. If Copilot regresses, per-tool Waiting + notification spam returns — the fix is to re-introduce a debounce or find a payload discriminator (e.g. `title`/`message`). **This ADR is where to look.**
- **Possible double notification.** The `notification` hook fires *because* the CLI emits a system notification, so Copilot may post its own OS notification alongside Abundio's away-gated one. Abundio cannot suppress Copilot's; disable it in Copilot's notification settings if doubled. Abundio's is the better one (only when the pane is off-screen, and clickable to the pane).
- **Non-digit/non-Enter approval keys.** Answering a prompt with a key the keystroke handler doesn't recognise (e.g. `y`) leaves the dot Waiting until `agentStop`. Low risk — Copilot's prompts are answered with a digit or Enter.
- **`exit_plan_mode` tool name.** Copilot's documented tool-name list includes `ask_user` but not `exit_plan_mode`; the scoped matcher is harmless if `exit_plan_mode` never matches.
