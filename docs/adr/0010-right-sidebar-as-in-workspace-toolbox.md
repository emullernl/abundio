# Right sidebar as in-workspace toolbox; left sidebar restricted to workspace navigation

Chrome flanking the workspace stack is split by purpose. The **left sidebar** lists the Workspaces in the active Profile and does nothing else — its job is *getting between Workspaces*. The **right sidebar** is the toolkit for the *active* Workspace: a three-tab strip across the top (**Git changes**, **Explorer**, **Search**) and the **Pull Requests** section always anchored below, collapsible. Explorer no longer lives in the left sidebar, Search no longer lives in the left sidebar, and the former "git panel" name retires — it now hosts three peers, not one feature.

**Side = purpose, not feature.** The left/right asymmetry is the load-bearing idea. A Workspace switch repaints everything in the right sidebar (its file tree, its git diff, its search index, the `*-repo` PR views) while the left sidebar stays put — because the left sidebar's job is selecting *which* Workspace, and the right sidebar's job is acting *within* one. This makes "what does each side mean?" a one-sentence answer instead of "Explorer is on the left because every editor does it that way, but Git is on the right because that's where it started".

**PRs are shared chrome, not a Git-tab affordance.** The Pull Requests section sits below the tab strip and persists across tab switches because PR review is workspace-level activity (review-requested and mine-all are account-wide; *-repo views are bound to the active Workspace's remote). Anchoring PRs outside the tabs also fixes a current UX bug — today, opening a non-git folder hides the whole PR section, even though `gh pr list --search "review-requested:@me"` works fine without a local repo. Under the new model, only the Git tab content and the `*-repo` PR views gate on git-repo-ness; account-wide PRs render regardless.

**One shortcut per tab, smart toggle.** `Cmd+Shift+G` → Git tab, `Cmd+Shift+E` → Explorer, `Cmd+Shift+F` → Search. Pressing the active tab's shortcut closes the right sidebar; pressing a different tab's shortcut opens-and-switches. No dedicated panel-toggle key — the tab keys do double duty. `Cmd+Shift+F` is rebound from "open Search in the left sidebar" to "open Search in the right sidebar"; muscle memory survives intact.

**Per-Window state, global dimensions.** Continuing the split established by ADR-0007: `rightSidebarOpen`, `rightSidebarActiveTab`, and `prSectionCollapsed` live in `windowUiStore` because they describe what the user is doing in *this* window. `rightSidebarWidth` and `rightSidebarPrRatio` live in `settingsStore` because they're "I always want it about this wide" preferences. A new Window opens with defaults: Git tab active, PRs expanded, right sidebar open.

## Considered alternatives

- **Keep Explorer on the left (status quo + add right-side PRs only).** The conventional editor layout. Rejected because it leaves the left sidebar's "purpose" ambiguous (workspace nav *plus* file tree *plus* search), and forces users into a two-axis mental model (left = "navigation" but also "files-of-the-current-workspace"). The proposed split makes the question "is this about *between* workspaces or *within* one?" answer the question "which side?" with no further thought.
- **Right sidebar as a VS Code-style permanent activity bar.** A 44px icon strip always visible, with content sliding out to its left. Rejected because Abundio's existing pattern (left sidebar) collapses its strip on collapse — adopting a permanent strip on the right would create two divergent collapse models in the same app. Symmetry with the left sidebar's collapse model won.
- **PRs as a fourth tab.** Trades a vertically split sidebar for a four-tab strip. Rejected because PR review is *parallel* to whatever else you're doing — you want to see "someone's waiting on you" while file-browsing or searching, not have to leave your current tab to check. The always-anchored section preserves that ambient awareness.
- **Global active-tab preference instead of per-Window.** Simpler. Rejected because multi-window flows (Window A = PR triage in Git tab, Window B = coding in Explorer tab) are exactly the case ADR-0007 was built for; tying tab choice to the Window matches the Profile-bound mental model.
- **Search-only stays on the left; Explorer moves right.** A halfway option keeping the left sidebar's split bottom panel for Search. Rejected because keeping a tab strip with one tab in it is dead chrome, and the "left = workspace navigation only" rule is cleaner when nothing else competes for the slot.

## Consequences

- `GitChangesPanel.tsx` renames to `RightSidebar.tsx`; `windowUiStore.gitPanelOpen` → `rightSidebarOpen`; `settingsStore.gitPanelWidth` → `rightSidebarWidth`; `settingsStore.gitPanelSplitRatio` → `rightSidebarPrRatio`. CONTEXT.md's "git panel" / "git changes panel" flagged ambiguity is retired; "Sidebar (Left | Right)" is now a domain term.
- `Sidebar.tsx`'s bottom-half tab strip (`sidebarBottomPanel: "explorer" | "search"`) is removed entirely. The `sidebarBottomPanel` setting key is deleted from localStorage on first load after the change ships (one-shot cleanup, no migration shim — the key has no analogue in the new layout).
- `windowUiStore` gains `rightSidebarActiveTab: "git" | "explorer" | "search"` (default `"git"`) and `prSectionCollapsed: boolean` (default `false`). These persist per-Window via the existing `windowUiStore` plumbing.
- The `Explorer` component's intra-tab "EXPLORER" uppercase header with collapse chevron is removed; the tab strip is now the header.
- The right sidebar's collapsed-strip widens its responsibility: three icons stacked (Git, Explorer, Search), the active tab's icon highlighted with the accent color. Clicking any icon expands the sidebar into that tab. The PR icon does *not* appear in the collapsed strip because PRs are not a tab.
- The non-git-repo short-circuit in the current `GitChangesPanel` is replaced by per-tab guards: the Git tab content renders `NotAGitRepoEmpty`; Explorer and Search render normally; the PR section renders `review-all` and `mine-all` normally while `*-repo` views show a "no GitHub remote" inline state.
- `Cmd+Shift+F`'s action changes from "open Search in the left sidebar's bottom panel" to "open Search in the right sidebar (smart toggle)". `Cmd+Shift+G` keeps its key but its semantics shift from "toggle git panel" to "toggle Git tab in right sidebar (smart toggle)". `Cmd+Shift+E` is newly bound to the Explorer tab with the same smart-toggle behavior.
- The `PanelTab` button component currently local to `Sidebar.tsx` is lifted into a shared `SidebarTab` used by both the (now-defunct) left-side and the new right-side tab strips — but in practice only the right sidebar needs it after this change, so it can stay co-located with `RightSidebar.tsx`.
